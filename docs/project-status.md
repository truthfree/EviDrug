# 프로젝트 상태

EviDrug는 질환과 후보 물질 입력부터 표적 탐색, 결합 가능성·ADMET 분석, 근거 종합과 저장
결과 재조회까지 연결합니다. 각 단계의 실행 상태, 출처와 한계를 분리해 보존합니다.

## 구현된 범위

- 공용 접근 코드 기반 세션과 요청 제한
- 질환 검색과 SMILES 검증
- Target Hypothesis, DTA, ADMET, Decision 단계 orchestration
- 분석 작업의 비동기 실행, 상태 기록과 중복 실행 방지
- 브라우저별 저장 결과 목록과 상세 결과 조회
- 공개 DTO를 통한 내부 실행 정보와 사용자 응답 분리
- 고정 모델·checkpoint identity와 실행 관측 저장
- replay와 continuation을 이용한 개발자 검증 경로

## 검증 범위

자동 테스트는 API 계약, 저장·복구, 도구 admission, projection, 부분 실패와 화면 표시를
검증합니다. 모델이 실행된다는 사실은 과학적 정확도나 임상적 유용성을 의미하지 않습니다.
예측 결과는 연구 우선순위와 추가 검증 항목을 구성하기 위한 보조 정보입니다.

## 알려진 한계

- 외부 데이터와 모델의 가용성·버전·적용 범위에 영향을 받습니다.
- DTA와 ADMET 예측은 결합 기전, 약효와 임상 안전성을 직접 증명하지 않습니다.
- 공용 접근 코드와 프로세스별 요청 제한은 대규모 공개 서비스용 사용자 인증·쿼터가 아닙니다.
- 저장된 과거 결과는 당시 모델, 데이터 조회 시점과 정책 버전에 종속됩니다.
- 실제 연구 의사결정에는 원문 근거 검토와 독립적인 실험 검증이 필요합니다.

세부 구현과 제약은 [기능 문서](features/), 현재 화면 흐름은
[현재 UX](ux/current-experience.md)를 확인하세요.
