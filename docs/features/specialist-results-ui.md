# 전문 결과 카드 UI (#112)

## 범위와 읽기 경로

[공개 결과 API](specialist-results-api.md)의 ADMET·DTA·Decision DTO만 표시한다.
백엔드 실행 정책·모델·프롬프트·캐시 및 API 계약은 변경하지 않는다.

- 실제 분석이 terminal 상태가 되면 `GET /api/v1/analyses/{id}/results`를 호출한다.
- 인증 작업공간의 **저장 결과**에서 기존 분석 ID를 명시적으로 조회할 수 있다.
- 조회 및 조회 재시도는 GET만 사용한다. 분석 생성, 재실행, provider/LLM 호출은 없다.
- 조회는 한 번의 snapshot이며 자동 polling하지 않는다. 진행 중 결과는 저장 결과 조회를
  다시 제출해 갱신한다. ID 변경/화면 종료 시 이전 요청을 취소하고 늦은 응답을 무시한다.
- 세션 쿠키를 포함하며 no-store를 지정한다. 다른 세션 또는 CLI replay 분석은
  서버의 소유권 정책에 따라 404로 안내한다. 접근 코드·쿠키를 별도로 저장하지 않는다.

## 표시 의미

- 분석 전체 상태, Agent 실행 상태, 공개 결과의 가용성을 구분한다.
- ADMET 12/49 같은 선택 요약을 부분 실행 실패로 설명하지 않는다.
  누락 항목, 모델 예측값·단위·백분위·종·출처, 한계를 따로 제공한다.
  예측값과 백분위의 독자용 표시는 DTA와 같은 숫자 표현 규칙을 사용한다.
  백분위는 신뢰도가 아니며 분류값을 임의로 양성/음성 또는 안전/위험으로 바꾸지 않는다.
- DTA는 후보별 상태와 모델별 `model_runs`의 점수 이름·독자용 수치·단위·모델·도구 호출 ID를
  각각 표시한다. 화면의 독자용 수치는 최대 소수점 둘째 자리로 표시하되 원래 numeric 값은
  API와 다운로드 JSON의 `value`에 보존하고, 다운로드에는 같은 규칙의 `display_value`를 함께
  제공한다. 두 pKd를 평균하거나 하나의 대표값으로 합성하지 않는다. 한 모델이
  실패/생략되어도 성공한 다른 모델의 예측값을 보존한다. LLM 해석 실패 시에도 가용한
  예측값을 표시한다. 과거 API 응답에 `model_runs`가 없으면 기존 대표 필드를 표시한다.
- 다운로드 JSON은 DTA 후보의 `experimental_evidence`, `evidence_assessment`,
  `evidence_errors`를 보존한다. 정량 assay는 원시 `value`와 독자용 `display_value`를 함께
  제공하며 원 레코드 ID, DOI/PMID와 추가 조회 상태를 누락하지 않는다.
- 다운로드 JSON은 Decision의 구조화된 `next_actions`와 cardiac follow-up 근거도 보존한다.
  `evidence_manifest`는 각 `used_evidence_ids`를 다운로드 내 위치에 연결하며, 하나라도
  연결할 수 없으면 보고서를 거부하는 대신 `evidence_audit.status`를 `audit_incomplete`로
  표시하고 `missing_evidence_ids`에 누락 ID를 명시한다. 과거 결과의 근거 공백을 성공으로
  가장하지 않는다.
- Decision은 추가 연구 우선/조건부 추가 연구/현재 근거로 우선하지 않음으로 표현한다.
- Decision의 구조화된 다음 행동은 판정과 근거 서술 바로 아래 별도 영역에 표시한다. 각 항목은
  아직 수행되지 않은 `제안`임을 명시하고 수행 내용, 제안 이유와 판정 변경 영향을 구분한다.
  실제 시스템 실행·완료 기록은 Agent 호출 흐름에만 표시하며 제안과 섞지 않는다. 과거 저장
  결과처럼 `next_actions`가 없으면 빈 목록으로 읽고 제공되지 않았다는 호환 안내를 표시한다.
  자유 문장의 숫자는 백엔드 표현을 그대로 사용하며 프론트에서 임의 반올림하지 않는다.
  임상 효능·안전성·치료 권고가 아니라 연구 우선순위라는 제한을 항상 표시한다.
- `invalid` 결과는 세부 내용을 숨긴다. `null` 결과를 0 또는 이전 성공 결과로 대체하지 않는다.
- 토큰은 원본 실행 당시 사용량이며 조회 비용이 아니다. `null`은 정보 없음이다.
- 긴 해석·근거 ID·실행 기록·ADMET 항목은 기본 접힘 상태의 native details로 제공한다.
  한국어 keep-all과 긴 식별자 wrapping, 좁은 화면의 1열 배치를 적용한다.
- 서버 문자열은 React 텍스트로 표시한다. 출처 URL은 http/https만 링크로 허용한다.

## 검증 자료와 결과

`specialist-api-summary.json`은 사용자가 제공한 breast cancer / CDK4 / palbociclib의
실제 공개 응답에서 실행 식별자를 합성 UUID로 치환한 자료다. 전체 실패 상태라도
ADMET은 완료되고 DTA·Decision은 실패한 원래 상태를 보존했다.
`specialistTestFixture.ts`의 DTA/Decision 추가 데이터는 UI 분기 검증용 합성 자료이며,
실제 성공 실행이나 과학적 판단을 증명하지 않는다. 운영 번들에서 import하지 않는다.

2026-09-22 검증:

- 프론트 테스트 10개 파일 / 79개 통과, 타입 검사·린트 경고 0건·프로덕션 빌드 성공.
- 잠금 파일 그대로 임시 디렉터리에 의존성을 설치하여 타입 검사·테스트·린트·빌드 검증.
  원래 node_modules는 디렉터리 교체 권한 문제로 직접 검증할 수 없었다.
- 공개 DTO/수치/ID 검증, 부분 실패와 해석 분리, XSS와 링크 방어, GET-only 조회,
  인증 오류와 재시도, 요청 취소/오래된 응답 무시, 기존 실행 화면 회귀 테스트 포함.
- 실제 LLM/provider 호출 및 새 분석 생성 없음.
- 사용자 제공 데스크톱 캡처에서 실제 저장 결과 조회, ADMET 완료/12-of-49 선택 요약,
  저장된 LLM 해석과 한계 펼치기, DTA·Decision 실패 코드와 원본 토큰 표시를 확인했다.
- 성공한 DTA·Decision의 실제 실행 결과 카드, 모바일 390px/320px 레이아웃과
  키보드 조작은 실화면 미검증이다. 브라우저 자동화 런타임 및 분리된 headless 브라우저가
  시작되지 않았다. 이 제한을 PR에 명시하며 전체 PoC 성공 검증과 구분한다.

## 사용자 검증 (PR 전)

1. 프로젝트 루트에서 `docker compose up -d --build --no-deps frontend`를 실행한다.
2. 기존 분석을 실행했던 브라우저 세션의 프론트 화면에서 **저장 결과**로 이동한다.
3. 분석 ID를 입력하고 조회한다. 새 분석 실행은 필요 없다.
4. 기존 `71c85585-3a7d-4a94-9f20-618b2aefe036`은 ADMET 완료, DTA·Decision 실패가
   올바른 과거 결과다. 코드 수정 후에도 이 과거 실행이 성공으로 바뀌지는 않는다.
5. ADMET 12/49와 값·단위·백분위, 실패 코드, 원본 토큰을 확인한다.
6. Tab/Enter로 세부 항목을 펼치고, 390px/320px 폭에서 긴 ID와 수치의 가로 넘침을 확인한다.
7. 개발자 도구에서 결과 조회에 GET만 발생하고 새 POST 분석 요청이 없는지 확인한다.

401/404이면 우선 원래 브라우저 세션과 ID를 확인한다. 세션이 만료되었다면 다시 로그인해도
과거 세션의 결과 접근이 복구되는 것은 아니다. 인증 정책을 우회하지 않는다.
