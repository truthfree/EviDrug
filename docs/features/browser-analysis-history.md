# 브라우저별 최근 분석 기록 (#176, #177)

## 배경과 목표

분석 ID를 직접 보관하지 않아도 같은 브라우저에서 재로그인한 후 최근 분석을 찾는다.
공용 접근 코드는 개인 계정이 아니므로 IP·User-Agent·브라우저 지문이나 접근 코드만으로
분석 소유자를 추정하지 않는다.

## 범위와 사용자 흐름

1. 접근 코드로 로그인하면 단기 인증 쿠키와 별개의 서명된 무작위 브라우저 ID 쿠키를 받는다.
2. 분석을 만들면 현재 인증 세션과 브라우저 ID의 해시를 함께 저장한다.
3. 저장 결과 화면은 최신 20개 분석의 입력 요약만 조회한다.
4. 사용자가 하나를 선택한 경우에만 기존 상세 결과 GET을 호출한다.
5. 로그아웃은 단기 인증 쿠키만 제거한다. 같은 브라우저에서 재로그인하면 브라우저 ID를
   유지하고 유효기간을 갱신한다.

목록은 질환명, 타깃 탐색/지정 여부와 지정 타깃, canonical SMILES, 생성 시각과 전체 상태만
공개한다. 화합물 이름은 현재 DB에 없으므로 추측하지 않는다. 목록·상세 조회는 저장된
자료만 읽으며 분석 생성, provider 또는 LLM 호출을 하지 않는다.

## API 계약

- `GET /api/v1/analyses`: `{ "items": [{ "analysis_id", "status", "disease_name",
  "target_mode", "target_name", "canonical_smiles", "created_at" }] }`. 최신 20개이며
  `Cache-Control: no-store`를 사용한다.
- `GET /api/v1/analyses/{analysis_id}` 및 `/results`: 현재 세션 또는 유효한 동일 브라우저
  ID에 속한 일반 분석만 허용한다. 그 외는 기존과 동일하게 404다.
- 모든 endpoint는 유효한 단기 인증 세션을 요구한다. 쿠키가 만료·변조된 경우 다른
  방문자의 기록으로 대체하지 않는다.

## 보안·복구 제약

- 브라우저 ID는 계정이 아닌 이 브라우저의 소유권 증거다. 서버는 쿠키 원문이 아닌
  해시만 분석 레코드에 보관한다. 운영 쿠키는 `Secure`, `HttpOnly`, `SameSite=Lax`다.
- 같은 브라우저를 공유하는 사람은 접근 코드를 알면 기록에 접근할 수 있다. 민감한
  데이터를 다중 사용자·다중 기기에서 안전하게 복구하려면 개인 계정이 필요하다.
- 기본 보관 기간은 90일이며 쿠키 삭제·만료·서명 비밀정보 교체 후에는 브라우저 소유권을
  복구할 수 없다. 과거 세션으로만 저장된 레코드를 새 브라우저 ID에 임의 귀속하지 않는다.
- 새 형식의 인증 쿠키에는 무작위 nonce가 들어간다. 배포 직후 구형 쿠키는 재로그인이
  필요할 수 있다. 개발 replay 분석은 목록·상세에 공개하지 않는다.

## 완료 조건

- 재로그인 후 같은 브라우저의 새 분석 목록과 선택한 상세만 조회할 수 있다.
- 다른 브라우저, 만료·변조 쿠키, 미인증 요청에는 목록·상세가 노출되지 않는다.
- 목록 응답은 입력 요약에 한정되고, 프론트 화면은 로딩·빈 목록·오류를 구분한다.
